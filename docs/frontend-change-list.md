# 前端修改清单

> 用于持续记录订单簿前端待修改事项。

## 1. 股票与基金分开处理

- 状态：待确认
- 优先级：待定

### 背景

当前页面将所有证券统一称为“股票”，股票代码和场内基金代码共用同一份 `symList`，仅在订单簿返回 `is_ETF` 时对价格小数位做差异化显示。

### 待修改内容

1. 在查询入口区分证券类型，例如“股票”和“基金”。
2. 根据证券类型分别展示或筛选可选代码，避免股票与基金混在同一个列表中。
3. 将页面中的“股票单号”“股票号”“股票代码”等文案调整为与当前证券类型一致的名称。
4. 股票继续按两位小数显示价格；ETF 等场内基金按三位小数显示价格。
5. 主订单簿查询、订单条件查询、数据生成页面应使用一致的证券类型和代码选择逻辑。
6. 页面刷新、路由跳转和订单自动定位时，应同时保存并恢复证券类型，避免只恢复代码后类型不一致。

### 需要后端确认

1. `symList` 是否可以返回证券类型，或是否提供分别查询股票、基金的参数/接口。
2. 基金范围是否只包含 ETF，还是还包含 LOF、封闭式基金等其他场内基金。
3. `is_ETF` 是否在所有快照接口中稳定返回。
4. 不同基金类型的价格精度和数量单位是否一致。

### 验收标准

- 用户可以明确选择“股票”或“基金”。
- 代码选择列表只显示对应类型的证券。
- 切换类型后，已选择的无效代码会被清空或重新校验。
- 股票价格显示两位小数，ETF 等场内基金按约定精度显示。
- 时间跳转、快照移动、订单查询和订单锁定对两类证券均可正常使用。
- 刷新页面或从全局订单查询跳转后，证券类型、证券代码和交易日期保持一致。

## 2. 订单悬停目前只显示订单 ID

- 状态：已确认
- 优先级：待定

### 问题表现

鼠标悬停在盘口订单格子上时，目前只能看到订单 ID，无法看到订单价格和创建时间。

### 排查结论

1. 后端 `snapshot_by_time` 返回的单笔订单包含 `order_local_id`、`remaining_volume`、`order_id` 和 `direction`，不包含 `price` 和 `create_time`。
2. 订单价格实际返回在所属价位层级的 `level.price` 中，但前端当前读取的是 `order.price`，因此价格为空。这属于前端字段映射问题。
3. 创建时间在当前快照响应的订单和价位层级中均未返回，前端没有可供展示的数据。这属于后端快照数据缺少字段，或需要后端提供其他可查询的订单时间来源。

### 待修改内容

1. 前端从订单所属价位的 `level.price` 获取价格，并按照股票两位、ETF 等场内基金三位小数格式化后展示。
2. 与后端确认是否可以在快照订单中增加 `create_time`，或者提供通过订单 ID 查询创建时间的接口。
3. 将悬停内容明确分行展示订单 ID、价格和创建时间；字段缺失时显示“暂无数据”，避免静默隐藏。

### 验收标准

- 任意有效订单格子悬停后均可看到订单 ID 和格式化后的价格。
- 后端提供创建时间后，悬停中可以正确显示该订单的创建时间。
- 股票与基金价格精度显示正确。

## 3. 多个同量订单只统计第一个锁定订单

- 状态：已确认
- 优先级：待定

### 问题表现

按数量锁定时可能同时锁定多个相同剩余量的订单，但当前每个价位只查找并统计第一个锁定订单。其他锁定订单没有独立的“单前/单后”统计，并可能被计入第一个锁定订单的“单后”数量。

### 待修改内容

1. 为同一价位中的每个锁定订单分别计算队列位置、前方手数、本单手数、后方手数及相应占比。
2. 多个锁定订单应有可区分的编号或订单 ID，用户可以通过点击或悬停查看指定订单的统计结果。
3. 不同买卖方向、不同价位的锁定订单分别在各自队列中统计，不混合计算。
4. 明确占比口径。建议以该价位完整队列总量为分母，使“单前、本单、单后”三项占比合计为 100%。

### 验收标准

- 同量订单被批量锁定后，每个锁定订单都有独立且正确的前后队列统计。
- 切换所查看的锁定订单时，显示的订单 ID、位置、手数和占比相互对应。
- 多个锁定订单不会相互覆盖统计，也不会只显示第一个订单的数据。

## 4. 订单查询目前不支持基金价格精度

- 状态：已确认
- 优先级：待定

### 问题表现

“查询订单并跳转到时间”中的订单价格输入框固定为两位小数。ETF 等场内基金通常需要三位小数，输入的三位价格会被四舍五入，导致提交给后端的价格与真实订单价格不一致，无法可靠匹配订单。

### 待修改内容

1. 订单查询弹窗需要获取当前证券类型或 `is_ETF` 标识。
2. 股票价格输入保持两位小数和 `0.01` 步长；ETF 等场内基金使用三位小数和 `0.001` 步长。
3. 查询请求必须保留用户输入的完整价格精度，不得在发送前截断或四舍五入成两位小数。
4. 与“股票与基金分开处理”共用证券类型判断逻辑，避免主盘口和订单查询的价格精度不一致。

### 验收标准

- 股票订单可以按两位小数价格正常查询和跳转。
- ETF 等场内基金可以按三位小数价格正常查询和跳转。
- 查询结果中的价格按当前证券类型正确格式化。
