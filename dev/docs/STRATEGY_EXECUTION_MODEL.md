# 策略订单撮合、收益可信度与后续演进思路

## 1. 本文前提

本文默认：仅包含历史订单时，使用 `csord` 新委托和 `cstra` 撤单重建出来的订单簿与撮合结果是正确的。

研究的问题不是历史市场能否重建，而是策略订单加入后：

- 怎样模拟成交；
- 是否消耗历史流动性；
- 怎样衡量策略收益的可信度；
- 怎样比较不同成交模型。

需要始终注意：历史数据记录的是“没有该策略参与”的市场。策略加入后的真实市场路径从未发生，因此历史数据无法提供策略反事实收益的唯一真值。

## 2. 当前代码的策略成交模型

当前实现是历史订单簿与策略虚拟成交混合的模型。

### 2.1 立即成交路径

`BacktestEngine::processUserOrder()` 先调用 `tryFillImmediately()`。只要限价能够穿过当前最优对手价，就会：

- 将策略订单全部标记为成交；
- 全部使用当前最优对手价；
- 更新策略回调和持仓；
- 不扣减历史对手订单；
- 不减少历史盘口数量。

### 2.2 策略挂单路径

未立即成交的策略订单会交给 `ConAuctionEngine`，并插入共享价格桶。历史订单与策略订单相遇时执行特殊虚拟成交：

- 只把策略订单标记为成交；
- 不扣减历史订单；
- 历史订单仍可继续与后续历史订单成交；
- 策略成交不会改变历史市场的成交容量。

此外，策略挂单目前不会调用 `bucketAdd()`，因此不会完整更新：

- 价格桶总量；
- 最优买价、最优卖价；
- 非空价格桶链表。

策略订单虽然插入 `Bucket::orders`，但如果该档位没有历史订单，它可能无法成为有效的最优价，也可能无法被正常扫描到。

## 3. 当前模型的主要缺陷

### 3.1 重复使用历史流动性

一笔历史订单可以先为策略提供虚拟成交，之后仍与原本的历史订单成交。同一份流动性在策略世界和历史世界中被重复使用。

### 3.2 成交量不受盘口数量约束

立即成交及 USER/BRK 虚拟撮合使用策略订单的全部剩余量，没有取策略剩余量和历史对手剩余量的最小值。因此，卖一只有 100 股时，策略买入 1,000 股仍可能被认为全部成交。

应至少满足：

```text
本档成交量 = min(策略剩余量, 本档可用对手量)
```

### 3.3 没有逐档成交

大额主动订单可能全部按照最优价成交，没有依次消耗卖一、卖二、卖三，因而低估滑点并高估收益。

合理结果应类似：

```text
买入 400 股：100@10.00 + 200@10.01 + 100@10.02
```

### 3.4 排队模型不完整

策略限价挂单应排在同价位先到的历史订单之后。只有前方队列被真实对手成交量消耗后，策略订单才应成交。

当前策略订单虽然可能进入桶内链表，但由于不完整参与价格桶维护，排队和最优价行为并不可靠。

### 3.5 盘口状态不守恒

真实成交应同时发生：

```text
买方剩余量减少 q
卖方剩余量减少 q
对应盘口量减少 q
累计成交量增加 q
```

当前虚拟成交只更新策略侧，无法满足双方数量守恒。

### 3.6 缺少部分成交状态的真实演化

策略订单可能应该经历：

```text
Submitted -> PartFilled -> PartFilled -> Filled/Cancelled
```

当前部分虚拟路径倾向于一次性全部成交，无法准确模拟剩余量、后续排队和撤单。

### 3.7 未充分模拟交易成本和执行条件

策略净收益还应考虑：

- 佣金、规费和印花税；
- 买卖价差；
- 跨档滑点；
- 信号计算、网络、柜台及交易所延迟；
- 撤单延迟及撤单前成交；
- 涨跌停、最小价格单位、最小申报数量和订单拒绝；
- 策略参与率及市场冲击。

## 4. 候选撮合实现方案

### 4.1 模型 A：改良的虚拟不消耗模型

历史订单簿独立重放，策略订单不改变历史订单的状态，但成交模拟应增加：

- 成交数量不能超过可见流动性；
- 主动单逐档成交；
- 挂单根据前方队列估计成交；
- 手续费、延迟和滑点；
- 防止同一历史流动性在同一策略或多个策略之间无限重复分配。

用途：策略规模极小、只希望估计“不影响市场时”的理想执行结果。通常可作为乐观模型，而不是最终真值。

### 4.2 模型 B：统一消耗撮合

输入事件为：

```text
csord 历史新委托
+ cstra 历史撤单
+ 策略委托/撤单
-> 同一订单簿、统一价格优先和时间优先撮合
```

规则包括：

- 策略订单和历史订单同等进入价格桶；
- 成交时双方都扣减数量；
- 支持部分成交、逐档成交和真实排队；
- 策略订单完整更新盘口和最优价；
- `cstra` 历史成交不强制驱动撮合，只用于校验；
- 历史撤单目标如果已被策略提前成交，则忽略该撤单并记录反事实冲突。

优点：订单簿内部一致、流动性不重复使用、成交约束更真实。

限制：策略已经改变市场，但未来历史参与者仍被假设按照原 `csord` 下单，未模拟他们对策略行为的响应。

### 4.3 模型 C：统一撮合加市场冲击

在模型 B 上增加：

- 下单和撤单延迟；
- 临时冲击和永久冲击；
- 大订单造成的后续报价恶化；
- 策略参与率限制；
- 更保守的排队位置；
- 不可见流动性和成交概率折扣。

用途：作为中性或悲观估计。其结果依赖冲击参数，参数需要用真实或模拟盘订单校准。

### 4.4 模型 D：代理人/生成式反事实市场

策略加入后，不再机械重放未来历史订单，而由市场参与者模型重新生成订单和撤单。

它在理论上最接近完整反事实市场，但模型风险极高、实现复杂，通常不适合作为当前项目的第一步。

## 5. 推荐的模型定位

建议同时保留多种模式，而不是只保留一个收益数字：

| 模式 | 定位 | 主要用途 |
|---|---|---|
| 改良虚拟模型 | 乐观结果 | 小策略、无市场冲击假设 |
| 统一消耗模型 | 中性基准 | 流动性守恒、排队和滑点 |
| 冲击/延迟模型 | 保守结果 | 容量与实盘风险评估 |

最终报告应展示收益区间及其假设，例如：

```text
乐观虚拟模型：100 万
统一消耗模型：55 万
延迟和费用模型：42 万
冲击悲观模型：25 万
```

收益对模型变化越稳定，策略可信度通常越高。

## 6. 收益差异的归因方法

### 6.1 可精确重算的顺序归因

如果所有模型和参数都已明确，可以按顺序逐项打开功能：

```text
M0：当前虚拟成交
M1：M0 + 盘口数量约束
M2：M1 + 逐档成交
M3：M2 + 排队规则
M4：M3 + 手续费
M5：M4 + 延迟
M6：M5 + 统一消耗
```

定义：

```text
某项顺序贡献 = PnL(Mi-1) - PnL(Mi)
```

在给定顺序和给定模型参数下，每一项都可以由回测精确重算，不需要主观拍一个数字。

但这不是唯一归因。功能之间存在交互，例如逐档成交会改变后续排队和持仓，手续费又取决于成交量。因此改变加入顺序，归因数字也可能改变。

### 6.2 顺序无关的平均边际归因

如果希望减少加入顺序的影响，可对不同功能开启顺序计算平均边际贡献，类似 Shapley 分解：

```text
某因素贡献 = 该因素在所有可能加入顺序中的边际 PnL 变化平均值
```

该方法能够公平分配交互效应，但随着因素数量增加，组合数量快速增长；实际可用抽样排列近似。

### 6.3 不能被历史数据精确确认的部分

即使归因计算在模型内是精确的，以下项目相对于真实反事实市场仍然只是估计：

- 策略订单会让其他参与者如何改价或撤单；
- 真实排队位置中的不可见细节；
- 未来流动性是否因策略出现而减少；
- 市场冲击系数；
- 实际系统延迟和订单拒绝概率。

因此必须区分：

```text
模型内精确归因 != 相对于真实市场的精确因果归因
```

归因结果应附带模型、参数和开启顺序，最好同时给出敏感度区间。

## 7. 收益可信度评价

在历史订单重建正确的前提下，重点检查：

- 策略成交是否满足价格、数量和队列约束；
- 策略成交量占同期市场成交量的比例；
- 单笔订单相对一档、十档流动性的比例；
- 放大订单规模后，成交率、滑点和单位收益是否合理恶化；
- 增加延迟、手续费和冲击后收益是否仍稳定；
- 历史撤单因策略提前成交而失效的数量；
- 不同模型下的成交量、均价、持仓和 PnL 差异。

建议进行订单规模压力测试：

```text
0.1x, 0.25x, 0.5x, 1x, 2x, 5x
```

合理结果通常是规模增加后总利润先上升，但成交率下降、滑点增加、单位收益下降，最终出现容量上限。

## 8. 券商模拟盘的常见实现

“模拟盘”不是一种统一技术，不同平台可能使用不同成交模型。常见类型如下。

### 8.1 行情驱动的纸面成交

策略订单只保存在券商或平台的模拟账户中，不送到真实交易所：

```text
真实行情 -> 模拟撮合器 -> 模拟成交/持仓/资金
```

它不会进入真实订单簿，也不会影响真实市场结构。常见简化规则包括触价即成交、按买一卖一成交，或者根据行情成交量估计成交。

### 8.2 基于真实行情的排队模拟

订单同样不送交易所，但模拟器使用逐笔委托、逐笔成交和盘口变化估计：

- 提交时的前方排队量；
- 后续对手成交量；
- 部分成交；
- 延迟和撤单结果。

它比简单纸面成交真实，但排队位置和不可见流动性仍是估计值，也不会改变真实市场。

### 8.3 交易所或券商仿真环境

订单进入一个独立于真实生产市场的仿真撮合系统，参与者可能都是测试账户或由系统生成。订单能影响仿真市场的订单簿，但不会影响真实生产市场。

### 8.4 小资金真实交易

只有订单真正被券商路由到真实交易所后，才会进入真实订单簿并影响市场。这已经属于实盘，不再是通常意义上的模拟盘。

### 8.5 模拟盘收益计算

模拟盘维护模拟现金、持仓和成交，通常按以下方式计算：

```text
已实现盈亏 = 平仓成交产生的买卖价差收益
未实现盈亏 = 当前估值价与持仓成本之差 * 持仓数量
净收益 = 已实现盈亏 + 未实现盈亏 - 手续费 - 税费 - 其他成本
账户权益 = 模拟现金 + 持仓市值
```

收益是否可信主要取决于模拟成交模型，而不是盈亏公式本身。触价即全部成交的模拟盘通常偏乐观；有逐笔排队、部分成交、延迟和费用的模拟盘更适合校准回测。

## 9. 下一步实现建议

建议按以下顺序演进：

1. 保留当前实现作为 `VirtualNoConsume` 基线；
2. 修复数量约束和逐档成交，形成改良虚拟模型；
3. 实现 `UnifiedConsume`，使策略订单完整参与价格桶和双方扣量；
4. 为每笔策略订单增加成交审计日志；
5. 建立不同模型间的成交与收益对比报告；
6. 增加手续费、延迟、参与率限制和冲击参数；
7. 使用模拟盘或小规模真实订单校准执行参数。

目标不应是寻找一个宣称“绝对准确”的收益值，而是得到：

```text
规则正确的成交结果
+ 可解释的收益差异
+ 对合理模型假设稳定的收益区间
```
